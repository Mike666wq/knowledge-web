# 1. Java中的内存分配

- 栈内存：方法被调用进栈执行，执行完毕出栈
- 堆内存：所有线程共享，存储对象、数组、字符串常量池
- 方法区：存储字节码信息

# 2. Java中对象的内存分配

- 第一步，先把`Memory.class`的字节码文件加载到方法区当中临时存储，然后执行`main方法`

![image-20260323234917815](07.面向对象原理篇/image-20260323234917815.png)

- `main方法`被调用时加载进`栈内存`，然后开始执行里面的第一段代码，就是创建一个`Student对象`，`Student对象`中包括两个属性和一个方法行为

![image-20260323235110100](07.面向对象原理篇/image-20260323235110100.png)

- 创建这个对象，虚拟机一共执行了7个动作
  - 1. 加载`class字节码`文件，把`Student类`的字节码文件加载到内存当中
    2. 申明局部变量，即对等号左边的局部变量`stu`进行申明
    3. 在堆中开辟空间，这一步对应的就是等号的右边，`new`的`Student`对象，在堆中开辟了小空间
    4. 默认初始化
    5. 显示初始化
    6. 构造方法初始化，这三步初始化都是给对象中的变量进行赋值
    7. 赋值地址值，就是把堆里面的地址值赋值给左边的`stu`

## 2.1 加载class文件

- 将`Student.class`的字节码文件加载到方法区里临时存储

![image-20260323235957846](07.面向对象原理篇/image-20260323235957846.png)

## 2.2 申明局部变量

- 就是等号左边对应的`Student stu`，此时在`main方法`里面就会多一个叫做`stu`的变量，前面的`Student`是`stu变量`对应的数据类型，表示这个变量能存储`Student`这个类对象的`地址值`
- `stu`表面上来说是对象名，但从内存的角度来说就是一个变量

![image-20260324000410427](07.面向对象原理篇/image-20260324000410427.png)

## 2.3 堆中开辟空间

- 对应等号右边的`new Student()`，此时有了`new关键字`，就是在堆中开辟了一个小空间，在堆中的空间都一个对应的`内存地址`
- 这个堆内存空间能存储的就是对应`Student对象`的各种属性以及`所有成员方法的地址`，成员方法的地址能够在之后使用对象调用方法的时候能找到对应的方法
- 这个堆内存对应的地址比如`ox0011`就是我们所说的对象，但这个对象还没有创建完毕，其中的属性都是没有值的

![image-20260324001024613](07.面向对象原理篇/image-20260324001024613.png)

## 2.4 默认初始化

- 此时就是对堆中创建的堆空间的对象的属性进行初始化

![image-20260324001205337](07.面向对象原理篇/image-20260324001205337.png)

## 2.5 显示初始化

- 在`javabean类`中定义成员变量的时候，就已经对类中的属性进行赋值，将属性的默认值替代了，此时就进行了显示初始化
- 一般在代码中不会使用显示初始化的，可以忽略

![image-20260325231700142](07.面向对象原理篇/image-20260325231700142.png)

## 2.6 构造方法初始化

- 调用构造方法给成员变量的属性进行赋值，一般都是使用空参构造方法，里面是不写代码的，所以这一步也可以忽略
- 但如果是使用的带全部参数的构造方法，那么此时成员变量的属性就有值了
- 构造方法只是创建对象中的一步

![image-20260325232205284](07.面向对象原理篇/image-20260325232205284.png)

## 2.7 赋值地址值

- 就是将堆内存中的对象的内存地址赋值给栈内存中的变量名如`stu`，通过这个内存地址就可以找到堆内存中的对象

![image-20260325232357671](07.面向对象原理篇/image-20260325232357671.png)

# 3. 对象在方法中进行传递

- 在`main方法`中调用`change方法`，`change方法`先进栈
- 方法中有一个传入的`stu形参`，是将`main方法`中`stu`记录的内存地址传给`stu形参`，此时`change方法`中的`stu变量`也能通过地址找到堆内存中的对象
- `change方法`里可以直接对堆内存中对象的属性进行修改

![image-20260325234501648](07.面向对象原理篇/image-20260325234501648.png)

- 之后`change方法`执行完毕从栈内存中出去，方法中的变量也随之消失
- 此时堆内存中的对象由于`main方法`中仍有变量在使用所以不会消失，但由于`change方法`的调用对象里面的属性发生了变化

![image-20260325234653247](07.面向对象原理篇/image-20260325234653247.png)

- 最后`main方法`出栈，对象没有变量使用也随之消失

![image-20260325234747307](07.面向对象原理篇/image-20260325234747307.png)
