# 从 `ai-agent-dev` 到本教程

本教程不是原课件的格式转换，而是一次结构、概念、代码和工程实践的整体重构。原目录保持不变，仅作为素材来源。

## 原课件审计结论

原课件覆盖 API、LangChain、工具、RAG、LangGraph、多 Agent、人机协作与部署等主题，适合作为知识点素材库，但存在以下关键问题：

- Prompt 在 Chain 之后讲解，认知顺序不合理。
- LangGraph 的状态、节点、边、条件和循环在多章重复，章节边界不清。
- Chain、Workflow 与 Agent 经常混用。
- 多个“Agent 项目”实际采用关键词路由、字符集合相似度或规则模拟。
- 原工具示例出现 `eval()`，不适合作为安全参考实现。
- RAG、工具调用、人机审批缺少超时、重试、空结果、重复执行和副作用处理。
- 原依赖清单遗漏实际使用的直接依赖，Notebook 的结构校验不能证明代码可运行。
- 多 Agent 早于成熟单 Agent，综合项目没有复用前面所学形成递进。

## 本次重构采用的原则

1. 先讲协议和数据流，再讲框架封装。
2. 明确区分 Chain、Workflow 与 Agent。
3. 先完成单 Agent，再进入规划、多 Agent 和人机协作。
4. 将规则模拟明确标为教学 Mock，不冒充真实模型决策。
5. 所有示例都设置终止条件，外部副作用增加权限与确认边界。
6. 用环境变量管理服务地址、模型和密钥。
7. 将状态、检查点、短期记忆、长期记忆和知识库分别解释。
8. 补齐测试、评估、可观测性、安全和成本控制。
9. 综合项目复用前述能力，而不是重新编写一个孤立 Demo。

## 代码真实性标识

- “纯 Python 示例”用于解释协议、状态或算法，不能自动获得模型能力。
- “Mock 示例”用于离线测试控制流，会在正文中明确标注。
- “在线示例”使用 OpenAI 兼容 API，需要有效模型配置。
- “生产建议”描述工程边界，不表示示例已覆盖所有企业基础设施。
