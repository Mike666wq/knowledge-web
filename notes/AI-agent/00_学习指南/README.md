# 00 学习指南

## 学习目标

完成本章后，你应能判断一个系统究竟是 Chain、Workflow 还是 Agent，理解整套教程的学习顺序，知道如何阅读示例，并建立“先验证、再扩展”的开发习惯。

## 关键术语

- **能力边界**：模型、工具和应用明确能做与不能做的范围。
- **最小可运行示例**：只保留理解一个概念所必需代码的示例。
- **参考实现**：包含参数校验、异常处理和测试，可作为项目起点的代码。
- **Mock**：用于离线模拟外部模型或工具行为的测试替身，不代表真实智能决策。
- **验收标准**：预先定义的可检查条件，例如输出结构正确、工具调用次数受限、引用可追溯。

## 这套教程解决什么问题

大模型应用不等于 Agent。普通聊天程序只完成一次或多次文本生成；Agent 会根据目标读取状态、选择动作、调用工具、观察结果并决定是否继续。教程的主线是先理解这个循环，再学习框架如何表达它。

## 三类系统先分清

- **Chain（链）**：步骤和顺序基本固定，例如“提取字段 → 翻译 → 格式化”。
- **Workflow（工作流）**：流程由开发者定义，可以有分支、循环、并行和人工审批。
- **Agent（智能体）**：模型在受约束的动作空间中动态决定下一步做什么。生产系统通常是“工作流负责边界，Agent 负责局部决策”。

## 学习方法

1. 先运行纯 Python 或最小 SDK 示例，理解数据如何流动。
2. 再使用 LangChain/LangGraph，理解框架抽象对应的原理。
3. 每章完成练习，不要只复制最终代码。
4. 任何能修改外部状态的工具都先加确认、权限和审计。
5. 用固定测试集验证变化，不凭聊天体验判断质量。

## 代码阅读顺序

看到一个 Agent 项目时，依次寻找：入口、状态结构、模型调用、工具定义、路由条件、终止条件、持久化、异常处理和测试。如果找不到最大步数或终止条件，Agent 可能陷入循环。

## 每章练习怎么做

每个练习建议分三次完成：第一次照着最小示例运行；第二次关闭参考代码独立实现；第三次主动加入一个失败场景，例如模型返回非法 JSON、工具超时、检索为空或审批被拒绝。Agent 开发的核心能力往往体现在失败路径，而不是理想路径。

建议建立自己的实验记录，至少写下：输入、预期、实际结果、日志、原因和修复。替换模型或框架版本时，重新运行固定测试集，不要只进行一次聊天测试。

## 常见学习误区

- 把一切大模型应用都叫 Agent，忽略是否存在动态决策和动作反馈。
- 只复制框架 API，不理解消息和状态的数据结构。
- 只验证成功回答，不验证超时、循环、越权和错误工具参数。
- 一开始就搭建多 Agent，尚未证明单 Agent 无法完成任务。
- 把更多上下文等同于更好效果，忽略上下文噪声和成本。
- 用提示词代替权限控制。提示词只能表达要求，真正的权限必须由代码和基础设施执行。

## 阶段验收

完成 01～06 后，应能手写一个有最大步数的工具调用循环；完成 07～09 后，应能解释检索、记忆、状态和检查点的区别；完成 10～12 后，应能设计带审批和终止条件的复杂流程；完成 13～16 后，应能提交包含测试、日志、评估和安全边界的项目。

## 版本说明

大模型框架变化较快。本教程使用主版本范围锁定依赖，并把模型名放入环境变量。若服务商不支持工具调用或结构化输出，需要更换模型，不能只修改提示词。

## 本章小结

学习 Agent 的顺序应从协议和数据流开始，再进入框架和复杂架构。后续每一章都应回答五个问题：输入是什么、状态如何变化、谁决定下一步、失败如何处理、何时终止。
