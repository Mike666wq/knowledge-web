# 13 Agent 工程化：从可运行 Demo 到可交付服务

## 学习目标

完成本章后，你应能：

1. 把模型、工具和工作流从 Web 接口中拆开，形成可替换的分层结构。
2. 使用环境变量管理配置和密钥，并在启动阶段完成校验。
3. 用 FastAPI 暴露健康检查与 Agent 调用接口。
4. 正确处理异步 I/O、超时、重试、并发和请求取消。
5. 记录结构化日志，同时避免泄露密钥、Prompt 和用户隐私。
6. 为服务定义“完成条件”，而不止是“本地能跑”。

## 前置知识

建议先完成工具调用、RAG、状态管理和 LangGraph 模块。你还需要理解 Python 函数、异常、`async/await`、类型标注和 HTTP 的基本概念。

## 1. 什么叫可交付

原课程 24～26 通过规则和小数据解释 RAG、工具与工作流，适合看清数据流；27 介绍了部署入口。但生产服务还必须回答：配置错误能否启动、请求超时怎么办、失败是否可重试、日志能否定位一次调用、并发是否安全、版本升级能否回归。

一个可交付 Agent 至少具有以下性质：

| 性质 | 可验证标准 |
| --- | --- |
| 可配置 | 密钥、模型名、超时和预算不写死在源码中 |
| 可启动 | 启动时校验配置，健康检查能区分存活与就绪 |
| 可取消 | 客户端取消后，不继续浪费模型与工具资源 |
| 可恢复 | 短暂网络故障可重试，永久错误立即失败 |
| 可观测 | 每次请求有 `request_id`，能看到阶段、耗时和结果状态 |
| 可测试 | 不连接真实模型也能测试主要控制流 |
| 可演进 | API、领域逻辑和外部适配器相互隔离 |

## 2. 关键术语

- **配置（Configuration）**：随环境变化、但不应写死在业务代码中的值，例如模型、服务地址和超时。
- **依赖注入（Dependency Injection）**：由外部创建并传入模型客户端、检索器或工具，而不是在函数内部固定实例化。
- **I/O 密集型任务**：主要时间花在网络、数据库或文件等待上的任务，适合异步并发。
- **超时（Timeout）**：单次操作允许占用的最长时间，是资源边界，不是重试间隔。
- **退避（Backoff）**：连续失败后逐渐延长等待时间；加入随机抖动可避免大量实例同时重试。
- **幂等性（Idempotency）**：同一操作执行多次，外部结果与执行一次相同。查询通常幂等，发邮件或扣款通常不是。
- **结构化日志**：用固定字段记录事件，便于机器检索和聚合，而非拼接随意字符串。
- **存活检查（Liveness）**：进程是否仍在工作；**就绪检查（Readiness）**：是否具备接收业务请求的条件。

## 3. 推荐分层

```text
HTTP/API 层          参数校验、状态码、请求 ID、鉴权
    ↓
Application 层       用例编排、超时、重试、预算、事务边界
    ↓
Domain 层            Agent 状态、策略、输入输出契约
    ↓
Adapters 层          模型、向量库、数据库、外部工具
```

API 层不应直接拼 Prompt，工具函数也不应知道 HTTP 状态码。这样测试领域逻辑时无需启动服务器，更换向量库时也不会重写路由。

建议的最小目录：

```text
app/
├── main.py              # FastAPI 入口与生命周期
├── config.py            # 配置读取与校验
├── agent.py             # 应用服务与领域结果
├── retry.py             # 可测试的重试策略
└── logging_config.py    # 日志字段与 request_id
tests/
```

## 4. 配置与密钥

配置应遵守三个规则：

1. `.env.example` 只写变量名和安全默认值，不写真实密钥。
2. 进程启动时完成类型转换与范围校验，不要等到第一个请求才报错。
3. 日志中只记录模型名、超时等非秘密配置；密钥、访问令牌和连接串必须脱敏。

```python
from dataclasses import dataclass
import os

@dataclass(frozen=True)
class Settings:
    model: str
    timeout_seconds: float

    @classmethod
    def from_env(cls) -> "Settings":
        model = os.getenv("LLM_MODEL", "mock-model").strip()
        timeout = float(os.getenv("REQUEST_TIMEOUT", "30"))
        if not model or not 0 < timeout <= 300:
            raise ValueError("模型名不能为空，超时必须在 0～300 秒之间")
        return cls(model=model, timeout_seconds=timeout)
```

`frozen=True` 让配置在运行期不可意外修改。真实项目可用 `pydantic-settings`，但配置原则不依赖具体库。

## 5. FastAPI 服务边界

FastAPI 负责协议适配，不负责 Agent 推理。推荐用应用工厂和 `lifespan` 管理客户端生命周期：启动时创建连接池，关闭时释放资源。不要为每个请求创建新的模型 HTTP 客户端。

状态码应表达错误类别：

| 场景 | 建议状态码 |
| --- | --- |
| 输入不符合数据模型 | 422 |
| 未认证/无权限 | 401/403 |
| 请求超过服务时间预算 | 504 |
| 上游限流，稍后可重试 | 429 或 503 |
| 业务策略拒绝危险动作 | 403 |
| 未知服务错误 | 500，同时返回不含内部细节的错误体 |

对外返回稳定的错误代码，例如 `agent_timeout`；堆栈只进入内部日志。

## 6. 异步不是“加上 async”

`asyncio` 的价值是等待一个 I/O 时让事件循环处理别的请求。以下场景必须区分：

- 异步 HTTP/数据库 SDK：直接 `await`。
- 阻塞 SDK：短期可用 `asyncio.to_thread` 隔离；长期应换异步客户端。
- CPU 密集计算：使用进程池或任务队列，不能放在线程事件循环中。
- 多个独立检索：用 `TaskGroup` 或 `gather` 并发，但要设置并发上限。

```python
async with asyncio.timeout(20):
    result = await agent.answer(question)
```

服务级超时必须包住整个用例；模型和工具还要有各自更短的超时。外层取消时，应继续传播 `CancelledError`，不要用宽泛的 `except Exception` 吞掉取消信号。

## 7. 重试的正确边界

只重试短暂错误：连接重置、网关暂时不可用、明确的限流。参数错误、权限错误、内容策略拒绝和解析契约错误通常不应原样重试。

安全重试需要同时满足：

- 操作幂等，或携带服务端支持的幂等键。
- 最大次数有限。
- 指数退避并加入抖动。
- 每次尝试受单次超时约束，整体仍受请求时间预算约束。
- 日志记录尝试次数和错误类型，不记录秘密参数。

非幂等工具应采用“先准备、再审批、最后提交”的两阶段设计。重试模型生成通常安全，重试“发送邮件”则可能发送多封。

## 8. 日志与请求关联

每条业务日志至少包含：

```text
timestamp, level, event, request_id, component,
duration_ms, attempt, outcome, error_type
```

推荐记录阶段事件：`request_started`、`retrieval_finished`、`tool_denied`、`model_finished`、`request_finished`。不要把完整 Prompt、检索原文、工具返回和密钥默认写入日志；需要调试时也应先脱敏并设置短保留期。

`request_id` 应通过上下文变量向下传播，使模型和工具日志可归属于同一次请求。它不是用户身份，也不能代替 trace id 或认证。

## 9. 并发、限流与背压

并发不是越高越好。模型供应商、数据库连接池和工具服务都有容量。可以用 `asyncio.Semaphore` 限制昂贵调用：

```python
model_slots = asyncio.Semaphore(8)

async with model_slots:
    return await model_client.generate(messages)
```

当队列已满时，应快速拒绝或排队到明确上限，这叫**背压（Backpressure）**。无限堆积请求只会把可控的过载变成长时间雪崩。

## 10. 常见错误

- 在路由函数里初始化模型、向量库和数据库连接。
- 用同一个超时值覆盖模型、工具和整个请求。
- 对所有异常无差别重试，包括 401 和参数错误。
- 在日志中记录 `Authorization`、完整用户文档或系统 Prompt。
- 用同步 SDK 阻塞异步路由。
- 只提供 `/health`，却不区分进程存活和依赖就绪。
- 把 mock 返回成功当成真实集成测试通过。
