# 文件上传漏洞完全指南

## 1. 文件上传漏洞概述

### 1.1 什么是文件上传漏洞

文件上传漏洞是指用户上传的文件没有经过充分的安全检查，导致攻击者可以上传恶意文件（如WebShell、木马程序等），从而获取服务器控制权或执行其他恶意操作。

### 1.2 文件上传漏洞的危害

- 上传WebShell获取服务器控制权
- 上传恶意脚本执行任意代码
- 上传病毒、木马危害服务器安全
- 上传畸形文件导致服务器崩溃
- 上传钓鱼页面危害用户安全

### 1.3 文件上传漏洞的检测方式

#### 1.3.1 前端检测

- **JavaScript检测**：在浏览器端通过JavaScript验证文件扩展名、MIME类型等
- **绕过方法**：
  - 禁用浏览器JavaScript
  - 使用Burp Suite、Yakit等代理工具修改请求
  - 使用浏览器开发者工具修改验证逻辑

#### 1.3.2 服务端检测

**MIME类型检测**：

- 检查HTTP请求头中的`Content-Type`字段
- 常见类型：
  - `image/jpeg`：JPEG图片
  - `image/png`：PNG图片
  - `image/gif`：GIF图片
  - `application/x-httpd-php`：PHP文件
- **绕过方法**：修改请求头中的Content-Type字段

**文件扩展名检测（黑名单）**：

- 禁止上传特定扩展名的文件
- 常见黑名单扩展名：
  ```
  .php .php3 .php4 .php5 .php7 .phtml .pht
  .asp .aspx .asa .asax .ascx .ashx .asmx
  .jsp .jspx .jspa .jsw .jsv .jspf
  ```
- **绕过方法**：
  - 使用大小写绕过：`.Php`、`.PHP`
  - 使用双写绕过：`.phpphp`
  - 使用特殊扩展名：`.phtml`、`.php5`、`.php7`
  - 使用解析漏洞：`.htaccess`、`.user.ini`

**文件扩展名检测（白名单）**：

- 只允许上传特定扩展名的文件
- 通常配合文件重命名使用
- **绕过方法**：
  - 截断攻击：`%00`截断
  - 解析漏洞：`.htaccess`、`.user.ini`
  - 二次渲染绕过

**文件内容检测**：

- **文件头检测**：检查文件开头的魔术字节（Magic Bytes）
  - JPEG：`FF D8 FF E0`
  - PNG：`89 50 4E 47 0D 0A 1A 0A`
  - GIF：`47 49 46 38`
  - PDF：`25 50 44 46`
- **绕过方法**：在文件开头添加对应的文件头

**图像检测函数**：

- `getimagesize()`：获取图片大小，检测是否为图片
- `imagecreatefromgif()`：创建图片资源，验证图片完整性
- **绕过方法**：
  - 图片马：在图片末尾附加PHP代码
  - 文件结构破坏：破坏图片结构使函数无法正确解析

### 1.4 常见文件解析漏洞

#### 1.4.1 Apache解析漏洞

- **.htaccess文件**：Apache配置文件，可以修改目录配置
  ```apache
  # 将jpg文件当作PHP解析
  <FilesMatch "jpg">
  SetHandler application/x-httpd-php
  </FilesMatch>
  ```
- **多后缀解析**：Apache从右到左识别扩展名，遇到不认识的就继续向左
  - `shell.php.xxx`：如果xxx不被识别，会解析为php
  - `shell.php.jpg`：如果php不被识别，会解析为jpg

#### 1.4.2 Nginx解析漏洞

- **空字节截断**：`shell.php%00.jpg`
- **路径解析**：`/upload/shell.jpg/x.php`
- **配置错误**：`cgi.fix_pathinfo=1`

#### 1.4.3 IIS解析漏洞

- **分号解析**：`shell.asp;.jpg`会被解析为asp
- **目录解析**：`/upload/shell.asp/shell.jpg`会被解析为asp
- **xx.asp目录**：`/upload/xx.asp/`下的文件都会被解析为asp

#### 1.4.4 Windows特性

- **::$DATA**：NTFS文件系统数据流，`shell.php::$DATA`等同于`shell.php`
- **点号截断**：`shell.php.`会被系统自动去掉末尾的点号
- **空格截断**：`shell.php `会被系统自动去掉末尾的空格
- **大小写**：Windows不区分大小写，`Shell.PHP`等同于`shell.php`

## 2. upload-labs靶场详解

### 2.1 第1关

- **检测方式**：前端JavaScript检测文件扩展名
- **绕过方法**：
  - 禁用浏览器JavaScript
  - 使用代理工具修改请求
  - 使用浏览器开发者工具删除验证代码

### 2.2 第2关

- **检测方式**：服务端MIME类型检测
- **绕过方法**：修改请求头中的`Content-Type`字段为`image/jpeg`

### 2.3 第3关

- **检测方式**：黑名单过滤，禁止`.php`扩展名
- **绕过方法**：使用PHP可解析的其他扩展名
  ```
  .php .phtml .php3 .php4 .php5 .php7 .phps .phar
  ```

### 2.4 第4关

- **检测方式**：黑名单过滤，但未禁止`.htaccess`
- **绕过方法**：
  1. 上传`.htaccess`文件：
     ```apache
     <FilesMatch "jpg">
     SetHandler application/x-httpd-php
     </FilesMatch>
     ```
  2. 上传包含PHP代码的图片文件（如`tz.jpg`）
  3. 访问`tz.jpg`，服务器会当作PHP解析

### 2.5 第5关

- **检测方式**：黑名单过滤，但有遗漏
- **绕过方法**：使用未被禁止的扩展名
  ```
  .php .phP .php5 .php4 .php3 .php2 .html .htm
  .phtml .pht .pHp .pHp5 .pHp4 .pHp3 .pHp2
  .Html .Htm .pHtml .jsp .jspa .jspx .jsw .jsv
  .jspf .jtml .jSp .jSpx .jSpa .jSw .jSv .jSpf
  .jHtml .asp .aspx .asa .asax .ascx .ashx .asmx
  .cer .aSp .aSpx .aSa .aSax .aScx .aShx .aSmx
  .cEr .sWf .swf .htaccess .ini
  ```

### 2.6 第6关

- **检测方式**：黑名单过滤
- **绕过方法**：文件名末尾加空格
  - 在代理工具中修改文件名为`shell.php `
  - 系统存储时会自动去掉末尾空格
  - 实际保存为`shell.php`

### 2.7 第7关

- **检测方式**：黑名单过滤
- **绕过方法**：文件名末尾加点号
  - 在代理工具中修改文件名为`shell.php.`
  - 系统存储时会自动去掉末尾点号
  - 实际保存为`shell.php`

### 2.8 第8关

- **检测方式**：黑名单过滤
- **绕过方法**：使用`::$DATA`特性
  - 上传文件名为`shell.php::$DATA`
  - Windows会自动忽略`::$DATA`部分
  - 实际保存为`shell.php`

### 2.9 第9关

- **检测方式**：黑名单过滤
- **绕过方法**：利用Windows通配符特性
  1. 第一次上传`tz.php:.jpg`，系统创建空文件`tz.php`
  2. 第二次上传`tz.>>>`，使用通配符匹配`tz.php`
  3. 文件内容被写入`tz.php`

### 2.10 第10关

- **检测方式**：黑名单过滤，将匹配的扩展名替换为空
- **绕过方法**：双写绕过
  - 上传文件名为`shell.pphphp`
  - 服务器将`php`替换为空后变成`shell.php`

### 2.11 第11关

- **检测方式**：文件存储路径可控
- **绕过方法**：`%00`截断
  - 将保存路径修改为`1.php%00`
  - 服务器会截断后面的路径
  - 最终保存为`1.php`

### 2.12 第12关

- **检测方式**：POST方式传递保存路径
- **绕过方法**：POST中的`%00`截断
  - 需要将`%00`解码为实际的空字节（0x00）
  - 使用代理工具修改请求体

### 2.13 第13关

- **检测方式**：文件头检测
- **绕过方法**：添加图片文件头
  - PNG文件头：`89 50 4E 47 0D 0A 1A 0A`
  - 在PHP文件开头添加图片头，使其通过检测

### 2.14 第14关

- **检测方式**：`getimagesize()`函数检测
- **绕过方法**：图片马
  - 将PHP代码附加到图片文件末尾
  - 示例：使用`copy`命令合并图片和PHP文件
    ```bash
    copy /b tz.jpg + shell.php shell.jpg
    ```
  - 需要配合文件包含漏洞执行

### 2.15 第15关

- **检测方式**：`imagecreatefromgif()`函数二次生成
- **绕过方法**：分析二次生成后的文件结构，在不变的区域添加PHP代码

### 2.16 第16关

- **检测方式**：图片压缩或加水印处理
- **绕过方法**：
  - 优选GIF格式（处理后变化较小）
  - 分析处理前后不变的区域
  - 在不变区域添加WebShell

### 2.17 第17关

- **检测方式**：服务器先下载后分析
- **绕过方法**：条件竞争
  - 使用暴力上传工具（如Yakit）
  - 在服务器删除文件前快速访问并执行
  - 利用时间差完成攻击

### 2.18 第18关

- **检测方式**：黑名单过滤
- **绕过方法**：参考前面的绕过技术

### 2.19 第19关

- **检测方式**：文件名截断
- **绕过方法**：利用`%00`或`/.`截断
  - 上传文件名为`1.php/.jpg`
  - 服务器会截断后面的部分
  - 实际保存为`1.php`

## 3. 文件上传防御

### 3.1 文件扩展名检测

- **使用白名单**：只允许上传特定扩展名的文件
- **文件重命名**：上传后随机重命名文件，避免直接使用用户上传的文件名
- **双重检测**：同时检测文件扩展名和MIME类型

### 3.2 文件内容检测

- **文件头检测**：检查文件开头的魔术字节
- **文件内容扫描**：使用杀毒软件或安全工具扫描文件内容
- **二次渲染**：对上传的图片进行重新渲染，破坏可能存在的恶意代码

### 3.3 存储安全

- **独立存储**：将上传的文件存储在独立的服务器或目录
- **禁止执行**：在上传目录中禁止执行脚本文件
- **文件权限**：设置合理的文件权限，避免直接执行

### 3.4 服务器配置

- **关闭危险函数**：禁用`exec`、`system`、`passthru`等危险函数
- **限制文件类型**：在服务器配置中限制可执行的文件类型
- **更新服务器**：及时更新服务器软件，修复已知漏洞

### 3.5 WAF防护

- **文件上传WAF**：使用专业的文件上传防护产品
- **规则防护**：配置WAF规则检测恶意文件上传
- **行为分析**：分析用户上传行为，检测异常操作
