# 中间件安全完全指南

## 1. 概述

在web安全中，中间件安全也是非常重要的一部分，而中间件的安全问题主要来自两个方面：

1. 中间件本身的开发缺陷导致的安全问题
2. 开发或运维人员在使用时进行了错误的配置而导致的安全问题

---

## 2. 基础知识

### 2.1 一次web访问的顺序

```bash
web浏览器 --> web服务器(狭义) --> web容器 --> 应用服务器 --> 数据库服务器
```

### 2.2 web服务器

广义：提供广义web服务的软件或主机

狭义：提供w3服务的软件或主机，即Web服务器软件或装有Web服务器软件的计算机。例如：IIS、Apache、nginx、Lighttpd。Web服务器可以处理HTTP协议，响应针对静态页面或图片的请求，进行页面跳转，或者把动态请求委托其它程序。

### 2.3 web容器

容器：作为操作系统和应用程序之间的桥梁，给处于其中的应用程序组件提供一个环境，使应用程序直接跟容器中的环境变量交互，不必关注其它系统问题。例如：tomcat（拥有JSP容器，servlet容器），Jboss(拥有EJB容器)。

### 2.4 应用服务器

中间件：为一种或多种应用程序提供容器，同时为应用程序提供相关服务。

应用服务器：用于被其他应用服务器或web服务器调用的中间件。例如Tomcat，WebLogic，WebSphere，Jboss，IIS，Tomcat，WebLogic，WebSphere即是应用服务器，又拥有web服务器的功能。

## 3. IIS

IIS是Internet Information Services的缩写，意为互联网信息服务，是由微软公司提供的基于运行Microsoft Windows的互联网基本服务。

**IIS目前只适用于Windows系统，不适用于其他操作系统。**

### 3.1 解析漏洞

#### 3.1.1 IIS 6.0

##### 基于文件名

该版本默认会将`*.asp;.jpg`此种格式的文件名，当成Asp解析，原理是服务器默认不解析;号及其后面的内容，相当于截断。

##### 基于文件夹名

该版本默认会将`*.asp/`目录下的所有文件当成Asp解析。

##### 其他可解析扩展名

IIS6.x除了会将扩展名为.asp的文件解析为asp之外，还默认会将扩展名为 `.asa`、`.cdx`、`.cer` 解析为asp。

**修复建议**：

1. 限制上传目录执行权限，不允许执行脚本
2. 上传文件之后重命名处理：时间戳或者随机数，让攻击者无法获知脚本具体的名字

#### 3.1.2 IIS 7.5

IIS7.x版本在Fast-CGI运行模式下，在任意文件，例：test.jpg后面加上`/.php`变成`test.jpg/.php`，会将test.jpg解析为php文件。

#### 3.1.3 PUT任意文件写入

在IIS中开启WebDav的地方，如果允许PUT方法，可以上传文件，然后使用MOVE方法修改文件后缀。

### 3.2 IIS短文件漏洞

攻击者可以利用~字符猜解或遍历服务器中的文件名，或对IIS服务器中的.Net Framework进行拒绝服务攻击。

**该漏洞的利用价值**：

1. 猜解网站的后台地址
2. 猜解敏感文件，例如网站备份的.rar、.zip、.bak、.sql文件等
3. 获取很多爬虫爬不到的未授权访问页面、获取WebService接口地址

**短文件名产生规则**：

- 当后缀小于4时，短文件名产生需要文件（夹）名前缀字符长度大于等于9位
- 当后缀大于等于4时，文件名前缀字符长度即使为1，也会产生短文件名

**支持的HTTP方法**：

目前IIS支持短文件名猜测的HTTP方法主要包括：DEBUG、OPTIONS、GET、POST、HEAD、TRACE六种

- IIS8.0之后的版本只能通过OPTIONS和TRACE方法被猜测成功
- IIS8.0以下版本需要开启ASP.NET支持

**扫描工具**：

```bash
# 项目地址：https://github.com/irsdl/IIS-ShortName-Scanner/tree/master
# 使用docker版本
docker run --rm registry.cn-hangzhou.aliyuncs.com/eagleslab/security:shortname 2 20 http://192.168.173.141/
```

## 4. Apache

### 4.1 解析漏洞

#### 4.1.1 文件解析

当Apache收到一个不认识的扩展名时，会从后往前解析，直到碰到认识的扩展名为止。

**示例**：

```
test.php.xxx
```

Apache会从后往前解析，xxx不认识，继续解析，php认识，所以当作php解析。

#### 4.1.2 .htaccess

`.htaccess`文件是Apache的目录级配置文件，可以覆盖Apache的主配置文件。

**利用方式**：

```apache
AddType application/x-httpd-php .jpg
```

将.jpg文件当作php解析。

### 4.2 配置错误

#### 4.2.1 目录遍历

Apache配置中如果启用了`Options Indexes`，当目录下没有默认首页文件时，会列出目录中的所有文件。

#### 4.2.2 信息泄漏

Apache配置中如果启用了`ServerSignature On`，会在页面底部显示服务器版本信息。

## 5. Nginx

### 5.1 解析漏洞

#### 5.1.1 配置错误

Nginx配置中如果将php交给本机的php-fpm处理，但没有正确配置，可能导致解析漏洞。

**错误配置示例**：

```nginx
location ~ \.php$ {
    fastcgi_pass 127.0.0.1:9000;
}
```

**利用方式**：

```
test.jpg/xxx.php
```

Nginx会将test.jpg交给php-fpm处理，导致解析为php。

#### 5.1.2 空字节截断

在Nginx的某些版本中，可以使用空字节截断文件名：

```
test.jpg%00.php
```

### 5.2 目录遍历

Nginx配置中如果启用了`autoindex on`，当目录下没有默认首页文件时，会列出目录中的所有文件。

## 6. Tomcat

### 6.1 解析漏洞

#### 6.1.1 PUT方法

Tomcat默认开启PUT方法，可以上传文件：

```
PUT /test.jsp/ HTTP/1.1
Content-Length: 23

<% out.println("hello"); %>
```

#### 6.1.2 后缀名解析

Tomcat只解析`.jsp`、`.jspx`、`.jspa`等后缀名，其他后缀名不会解析。

### 6.2 弱口令

Tomcat默认用户名密码：`admin/admin`或`tomcat/tomcat`

## 7. WebLogic

### 7.1 漏洞

- 反序列化漏洞（CVE-2015-4852）
- SSRF漏洞
- 强制认证绕过

### 7.2 弱口令

WebLogic默认用户名密码：`weblogic/Oracle@123`

---

## 8. 防御措施

1. **及时更新中间件版本**：修复已知漏洞
2. **正确配置中间件**：关闭不必要的功能和端口
3. **限制文件上传**：限制上传目录执行权限
4. **使用WAF**：部署Web应用防火墙
5. **定期安全审计**：检查中间件配置和日志
