# 1. 常见监控软件介绍

### 📊 1. Cacti

- **核心定位**：一款基于 **PHP + MySQL + SNMP + RRDTool** 的网络流量与性能监控工具，专注于图形化展示。
- **工作原理**：通过 **轮询** 方式，由主服务器定时向设备请求数据。
- **主要特点**：
  - **图形强大**：擅长绘制历史趋势图，适合观察流量、CPU、磁盘等指标的长期变化。
  - **告警薄弱**：本身不擅长实时告警，需依赖其他系统（如Nagios）或插件实现异常通知。
- **适用场景**：对历史数据可视化要求高，但告警需求简单的网络设备和基础资源监控。

------

### 🚨 2. Nagios

- **核心定位**：一款老牌、开源的网络与主机监控报警系统，核心优势在于 **告警能力** 和 **插件扩展**。
- **监控范围**：支持主机存活、服务状态（HTTP/FTP等）、系统资源（CPU/内存/磁盘）及网络设备（交换机/路由器）等。
- **主要特点**：
  - **告警灵活**：支持邮件、短信等多种告警方式，并可自定义事件处理逻辑。
  - **扩展性强**：拥有庞大的插件生态，可监控几乎所有IT基础设施。
  - **图形一般**：自带界面侧重状态展示，图表美观度不足，通常与Cacti等工具配合使用。
- **适用场景**：追求稳定可靠告警，且监控规模在数千台服务器级别的传统运维环境。

------

### 🧠 3. Ganglia

- **核心定位**：由UC Berkeley发起，专为 **大规模集群**（尤其是Hadoop生态）设计的分布式监控系统。
- **核心组件**：`gmond`(节点数据采集)、`gmetad`(数据聚合) 和 Web前端。
- **主要特点**：
  - **高性能**：专为高并发、大规模节点设计，对系统资源消耗小。
  - **实时性强**：擅长实时展示集群中每个节点的CPU、内存、网络等性能指标。
  - **集群友好**：是Hadoop官方推荐的监控方案之一，便于横向扩展。
- **适用场景**：监控大规模服务器或Hadoop/Kafka等分布式集群的性能指标。

------

### 🚀 4. Zabbix

- **核心定位**：一套企业级的 **分布式监控解决方案**，集数据采集、告警、可视化于一体。
- **核心功能**：
  - **全面监控**：覆盖服务器、网络设备、应用、服务等多种对象。
  - **方式多样**：支持 **主动** 与 **被动** 两种数据收集模式，并兼容Agent、SNMP、JMX等多种协议。
  - **强大告警**：提供灵活的告警规则和通知渠道（邮件、短信等）。
  - **可视化佳**：内置功能强大的Web界面，支持自动发现、模板化配置和丰富的图表展示。
-  **适用场景**：适用于从几十到上万台设备的复杂环境，是传统运维和云环境下的主流选择。

------

### 📈 5. 主流监控软件对比

| 软件        | 核心优势             | 图形能力       | 告警能力       | 适用场景                            |
| ----------- | -------------------- | -------------- | -------------- | ----------------------------------- |
| **Cacti**   | 历史数据趋势图       | **非常强**     | 弱，需二次开发 | 网络流量、基础资源的可视化展示      |
| **Nagios**  | 稳定、灵活、告警强大 | 一般，依赖插件 | **非常强**     | 对告警可靠性要求高的传统IT环境      |
| **Ganglia** | 专为大规模集群设计   | 适合集群展示   | 一般           | 大规模Hadoop、Kafka等分布式集群监控 |
| **Zabbix**  | 功能全面，一体化方案 | **强**         | **强**         | 从中小规模到大规模、复杂的混合环境  |

# 2. Zabbix监控简介📖

- 一句话概括：**Zabbix 是一个企业级、开源、分布式的监控平台，通过 Web 界面统一监控服务器和网络设备的“健康状况”和“性能指标”，并在出现问题时及时告警。**

  - **核心功能**：监控 CPU、内存、磁盘、网络流量、服务状态、日志等，保障线上业务稳定运行。

  - **工作原理**：通过在被监控主机上部署 Agent 或使用 SNMP 等协议采集数据，上报给 Zabbix Server，Server 将数据存入数据库，最后通过 Web 界面进行展示、绘图和告警。
  - **核心优势**：开源免费、功能全面、支持分布式和自动化，是运维监控领域的主流选择。

## 2.1 zabbix优点✅

- **开源免费**：无软件授权成本，源代码开放，可自由使用和二次开发。

- **资源占用低**：Zabbix Server 对服务器性能要求不高，适合长期稳定运行。

- **监控范围广**：自带丰富的监控模板，支持 Linux/Windows 服务器、网络设备（交换机/路由器）、数据库、中间件等。

- **易于扩展**：支持分布式监控和自动发现功能，可轻松管理大规模设备集群。

- **高可定制**：提供开放的 API 接口，方便与 CMDB、工单系统等第三方平台集成。

## 2.2 zabbix缺点⚠️

- **数据库压力大**：所有监控数据都存储在数据库中，随着时间推移，数据量巨大，容易成为性能瓶颈。

- **配置繁琐**：对大量主机进行批量修改时，操作不够便捷，需要依赖模板或脚本。

- **学习成本**：虽然入门简单，但要实现复杂的监控需求，需要深入理解其架构和原理，并进行二次开发。

- **告警噪音**：默认配置下，系统级别的告警较多，容易形成“告警风暴”，需要管理员进行精细化的过滤和调优。

## 2.3 zabbix组件结构🏗️

Zabbix 的架构可以看作一条完整的数据流水线：**Agent 采集 → Server 处理 → 数据库存储 → Web 展示**。各组件协同工作，具体如下：

| 组件                  | 核心职责                                                     |
| --------------------- | ------------------------------------------------------------ |
| **Zabbix Server**     | 整个监控系统的“大脑”，负责接收数据、处理告警、执行任务调度。 |
| **数据库 (Database)** | 存储所有配置信息、监控数据和历史记录，是 Zabbix 的数据基石。 |
| **Web 界面**          | 提供图形化的操作平台，用于配置监控、查看图表和接收告警，通常与 Server 同机部署。 |
| **Zabbix Proxy**      | (可选) 部署在监控节点众多的环境中，作为 Server 的“代理”，分担数据采集压力，适用于跨机房场景。 |
| **Zabbix Agent**      | (可选) 部署在被监控主机上，负责采集本机数据并发送给 Server 或 Proxy。 |

## 2.4 zabbix监控方式🔄

Zabbix 支持两种数据收集模式，理解它们的区别是配置的关键：

| 模式                   | 通信方向       | 核心特点                                                     |
| ---------------------- | -------------- | ------------------------------------------------------------ |
| **被动模式 (Passive)** | Server → Agent | **Server 主动拉取数据。** 配置简单，但 Server 负载随监控项增多而增大。 |
| **主动模式 (Active)**  | Agent → Server | **Agent 主动上报数据。** 能显著减轻 Server 的压力，更适合大规模监控场景。 |

**💡 实践建议**

在实际生产中，通常结合使用两种模式：对核心关键主机使用**被动模式**确保数据实时性；对海量普通主机使用**主动模式**以优化 Server 性能。

## 2.6 Zabbix常用术语

以下是 Zabbix 中的几个核心概念，理解它们是掌握 Zabbix 的关键：

| 术语                    | 核心定义                                                | 关键点                                                       |
| ----------------------- | ------------------------------------------------------- | ------------------------------------------------------------ |
| **主机 (Host)**         | 被监控的网络设备或服务器，通过 IP 或域名标识。          | 监控的**最小单位**，所有监控项都挂载在主机上。               |
| **主机组 (Host Group)** | 主机的逻辑集合，用于分类管理（如 Web 服务器、数据库）。 | 主要用于**权限控制和批量管理**，不直接关联监控数据。         |
| **监控项 (Item)**       | 从主机上采集的具体指标，是 Zabbix 数据的最小单元。      | 每个监控项都有一个唯一的 **Key** 来标识，如 `system.cpu.load`。 |
| **触发器 (Trigger)**    | 定义监控项数据的“阈值规则”，并根据数据状态判断问题。    | 状态在 **OK** (正常) 和 **Problem** (问题) 之间切换，是**告警的核心**。 |

# 3. Zabbix-server部署

## 3.1 安装Zabbix 服务端

- 准备zabbix的yum源，这里通过安装zabbix-release软件包来自动获取zabbix的源。然后安装服务端相关组件

- 官网地址：https://www.zabbix.com/

```bash
[root@localhost ~]# rpm -Uvh https://repo.zabbix.com/zabbix/6.0/rhel/9/x86_64/zabbix-release-latest-6.0.el9.noarch.rpm
[root@localhost ~]# yum install -y zabbix-server-mysql zabbix-web-mysql zabbix-apache-conf zabbix-sql-scripts zabbix-selinux-policy zabbix-agent --nobest

# 安装中文插件
[root@localhost ~]# yum install -y glibc-langpack-zh.x86_64
```

- 关闭防火墙和Selinux

```bash
[root@localhost ~]# setenforce 0
[root@localhost ~]# vim /etc/selinux/config

[root@localhost ~]# systemctl stop firewalld
```

### 5.2.3 创建python脚本

由于zabbix无法直接向钉钉发送告警信息，所以这里需要借助python脚本来实现，让zabbix调用python脚本来向机器人接口发送信息

- 安装requests模块

```bash
[root@server1 ~]# yum install -y python-requests
```

- python脚本如下：

```bash
[root@server1 alertscripts]# cd /usr/lib/zabbix/alertscripts
[root@server1 alertscripts]# vim zabbix_send_ding.py 
#!/usr/bin/python
# -*- coding: utf-8 -*-
# Author: Aaronxu
import requests
import json
import sys
import os

headers = {'Content-Type': 'application/json;charset=utf-8'}
api_url = "https://oapi.dingtalk.com/robot/send?access_token=8eab8f6f2d872a0e14376fd782b6aaf40bd57b1352f9cc8ed42c238baaec80e0"
def msg(text):
    json_text= {
    "msgtype": "text",
    "at": {
        "atMobiles": [
            "18888888888"
        ],
            "isAtAll": True
     },
     "text": {
        "content": text
     }
    }
    response = requests.post(api_url,json.dumps(json_text),headers=headers).content
    print(response)

if __name__ == '__main__':
# 这里用发送关键字用来触发告警
    text = "告警"
# 使用sys.argv来接收一个参数，该参数是zabbix发送的消息
    # text = sys.argv[1]
    msg(text)
```

- 测试脚本
